NEXUS VAULT v2.0 — Enterprise Microservices Games StoreA full-stack, multi-service digital game storefront built with Java 21, Spring Boot 3.3.5, Spring Security, and MySQL 8.0, designed for bare-metal EC2 deployment and containerized orchestration on Docker Swarm.1. Architecture & Microservices OverviewThe application is split into 4 independent Spring Boot microservices backed by MySQL 8.0:Service ModulePortDatabase SchemaResponsibilitystorefront-ui8080None (Stateless UI)Spring Security login/logout, Thymeleaf UI, genre filter, routes requests to backend APIscatalog-service8081games_dbStores & seeds 6 AAA titles (games table), filters by genre, validates promo codesorder-service8082orders_dbValidates game & promo via catalog-service, calculates discounts, generates NXV-XXXX-XXXX activation keys (game_orders table)review-service8083reviews_dbStores & seeds player ratings and reviews (game_reviews table)2. Environment & Prerequisites (Ubuntu 24.04 EC2)System Packages RequiredInstall Java 21 JDK, Apache Maven, MySQL Server 8.0, and Git:sudo apt update && sudo apt install -y openjdk-21-jdk maven mysql-server git
EC2 Security Group Inbound RulesConfigure the following inbound TCP rules on your EC2 Security Group:Port 22 (SSH): Administrative terminal accessPort 8080 (HTTP): Public browser access to storefront-ui (ports 8081–8083 and 3306 remain private to localhost / internal Docker overlay networks)3. MySQL Database ConfigurationStart & Enable MySQL:sudo systemctl enable --now mysql
Create the Dedicated JDBC Application User:
Ubuntu 24.04 configures root@localhost with auth_socket by default, which rejects TCP/JDBC connections from Java. Create a dedicated gamestore user with full schema creation privileges:sudo mysql -e "CREATE USER IF NOT EXISTS 'gamestore'@'localhost' IDENTIFIED BY 'root123'; GRANT ALL PRIVILEGES ON *.* TO 'gamestore'@'localhost' WITH GRANT OPTION; FLUSH PRIVILEGES;"
Docker / Remote DB Note: When running MySQL in a container or on a separate host, grant access to 'gamestore'@'%' instead of 'localhost'.Auto-Created Schemas & Tables:
Manual CREATE DATABASE or CREATE TABLE statements are not required. Each backend service configures createDatabaseIfNotExist=true and spring.jpa.hibernate.ddl-auto=update:games_db.games — Auto-created and seeded with 6 AAA titles on first startup if empty.orders_db.game_orders — Auto-created on startup; stores completed orders and activation keys.reviews_db.game_reviews — Auto-created and seeded with 3 sample reviews on first startup if empty.4. Build & Startup Procedure (EC2 Host)Step 1: Clone & Compile All 4 Modulesgit clone https://github.com/krishna-1122/premium-games-store.git
cd premium-games-store
mvn clean package -DskipTests
This builds 4 executable Spring Boot fat JARs:catalog-service/target/catalog-service-2.0.0.jarorder-service/target/order-service-2.0.0.jarreview-service/target/review-service-2.0.0.jarstorefront-ui/target/storefront-ui-2.0.0.jarStep 2: Start Services in Dependency OrderLaunch the 3 backend APIs first (catalog $\rightarrow$ order $\rightarrow$ review), giving Hibernate ~12 seconds per service to initialize schemas before starting storefront-ui:DB_USER=gamestore DB_PASSWORD=root123 nohup java -jar catalog-service/target/catalog-service-2.0.0.jar > catalog.log 2>&1 &
sleep 12
DB_USER=gamestore DB_PASSWORD=root123 nohup java -jar order-service/target/order-service-2.0.0.jar > order.log 2>&1 &
sleep 12
DB_USER=gamestore DB_PASSWORD=root123 nohup java -jar review-service/target/review-service-2.0.0.jar > review.log 2>&1 &
sleep 12
nohup java -jar storefront-ui/target/storefront-ui-2.0.0.jar > ui.log 2>&1 &
Step 3: Stop All Running Servicespkill -f "catalog-service|order-service|review-service|storefront-ui"
